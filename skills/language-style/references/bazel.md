# Bazel / Starlark

- ユーザー向けの `.bzl` のエントリポイントは浅い階層に置く（`rules_*` のスタイル）。内部の実装はサブディレクトリに置く。
- 出力は現在のラベルに基づいて命名し、衝突を避ける。ルールのすべての属性に doc を書く。
- ヘルパーは追加の出力、環境変数、provider を返し、`ctx.actions.run` はルールの実装側が呼ぶ。クラスのような struct を作らない。
- 依存の型チェックには provider を使う。強力なルール（例: `rules_pkg`）は安全なサブセットだけを公開するようラップする。
- 暗黙の glob や、暗黙に生成されるターゲットを避ける。生成するファイルでは dict のキーをソートする。
- hermeticity、リモートキャッシュ、RBE の制約を意識する。計測せずにアクションへ `no-remote` タグを付けない。
